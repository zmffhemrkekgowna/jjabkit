# JJabKit (짭킷) — 최종 통합본

뮤지컬·연극 캐스팅 스케줄 앱이에요. Next.js 15 + Tailwind CSS 3 + Supabase(PostgreSQL, Auth, Storage)로 만들었어요.

- 누구나: 공연 목록·상세·캐스팅 스케줄·할인/이벤트 보기, 하트로 관심 공연·관심 배우 등록, 마이페이지에서 관심 배우 일정 모아보기, 상단 종 아이콘으로 업데이트·소식 보기, 달력 공유 및 PNG 저장
- 관리자(나)만: 공연·배역·배우·회차 등록·수정·삭제, 포스터 업로드, 소식(공지) 등록·수정·삭제, 전체 데이터 JSON 백업·복구

권한 구조와 데이터 구조의 자세한 내용은 `docs/PERMISSIONS.md`, 배포는 `DEPLOY.md`를 보세요.

## 권한 한눈에 보기

| 기능 | 일반 방문자 | 관리자 |
| --- | :---: | :---: |
| 공연 목록, 상세, 캐스팅 스케줄, 할인·이벤트 보기 | O | O |
| 하트 토글(관심 공연·관심 배우, 내 브라우저에 저장) | O | O |
| 마이페이지(관심 공연·관심 배우·관심 배우 일정·내 일정) | O | O |
| 업데이트·소식 보기(종 아이콘, 새 소식 N 배지) | O | O |
| 캐스팅 달력·관심 배우 일정 공유하기, PNG로 저장 | O | O |
| `/admin` 접근, 데이터 등록·수정·삭제 | X | O |
| 소식(공지) 등록·수정·삭제 | X | O |
| 전체 데이터 JSON 내려받기·불러오기 | X | O |

`/admin`은 세 겹으로 막혀요. ① `middleware.ts`(서버) ② `app/admin/(protected)/layout.tsx`(서버) ③ Supabase RLS(DB, 진짜 보안 경계). 하트는 서버로 가지 않고 방문자의 브라우저(localStorage)에만 저장돼요.

## 시작하기

1. Supabase 프로젝트를 만들고, SQL Editor에서 `supabase/migrations/0001_init.sql` 전체를 실행한 다음 `supabase/migrations/0003_notices_backup.sql`도 실행해요. (표, RLS 정책, 권한 정리, 포스터 저장소 / 소식 표와 백업 불러오기 함수. 이어서 `supabase/migrations/0004_events_popups.sql`(이벤트·팝업 표), `supabase/migrations/0005_site_pages.sql`(소개·개인정보처리방침·문의 문구 표), `supabase/migrations/0006_event_color.sql`(이벤트 막대 색), `supabase/migrations/0007_site_pages_custom.sql`(직접 만드는 안내 페이지), `supabase/migrations/0008_atomic_admin_ops.sql`(관리자 일괄 작업을 한 번에 처리하는 함수)도 실행해요. 0003~0008을 빼먹으면 그 기능만 안 되고 나머지는 그대로 동작해요)
2. Authentication > Users에서 내 이메일·비밀번호로 사용자를 추가하고, **신규 가입(sign up)은 꺼요.** SQL Editor에서 관리자로 등록해요.
   ```sql
   insert into public.admins (user_id)
   select id from auth.users where email = 'me@example.com';
   ```
3. (선택) `supabase/seed.sql`을 실행하면 샘플 공연 5개가 들어가요.
4. `.env.local.example`을 `.env.local`로 복사해 프로젝트 URL과 공개 키를 넣어요. (`service_role` 키는 넣지 않아요)
5. `npm install` 후 `npm run dev` 를 실행해요.
6. `/admin/login`에서 로그인하고 `/admin`에서 데이터를 입력해요.
7. `supabase/tests/rls_check.sql`을 SQL Editor에서 실행해 권한을 점검해요. `ERROR: RLS 점검 결과`로 나오고 모든 줄이 `PASS`이면 정상이에요. (일부러 오류를 내 점검용 데이터를 모두 되돌려요)

## 동작 규칙

- 배우 필터: 다른 배역의 배우를 함께 고르면 모두 출연하는 회차만, 같은 배역에서 여러 명을 고르면 그중 한 명이라도 출연하는 회차가 표시돼요.
- 관심 배우는 이름으로 저장해서, 같은 배우가 여러 공연에 나오면 관심 배우 일정에 한꺼번에 모여요. (동명이인은 같이 묶여요)
- 관리자 입력: 글자 입력은 칸을 벗어나거나 Enter를 눌렀을 때, 선택·체크박스는 바로 저장돼요.
- 같은 공연의 같은 날짜·시간 회차는 중복 등록이 막혀요. 배우를 삭제하면 그 배우의 회차는 "미정"이 돼요.

## 확인한 것과 아닌 것

- 확인함(코드): 타입 검사와 `next build` 통과, 배우 필터·하트·마이페이지 동작을 가상 브라우저로 점검.
- 확인함(권한, 가짜 Supabase 서버로 실제 앱 실행): 방문자는 목록·상세·마이페이지가 열리고 `/admin`은 로그인 화면으로 가며, 위조 토큰과 관리자가 아닌 계정도 차단되고, 관리자는 열려요. 인증 서버가 응답하지 않을 때도 `/admin`은 열리지 않아요. 보안 헤더와 검색 제외(noindex)도 확인했어요. (19개 항목)
- 확인함(DB, 실제 PostgreSQL 16에 Supabase와 같은 기본 권한을 흉내 내 적용): 방문자·일반 계정·관리자별 읽기·쓰기 권한 25개 항목이 모두 통과해요.
- 확인함(소식·백업·이미지, 이번 추가분): 백업 만들기·검사 25개 항목(Node), 새 표와 `import_shows()`의 권한·검증·전부 취소 동작 41개 + 점검 스크립트 33줄(실제 PostgreSQL 16), 소식 모달·N 배지·공유·PNG 저장·관리자 소식 등록/수정/삭제·백업 불러오기 흐름 49개(실제 Chromium, Supabase는 가짜로 대체), 달력 PNG를 실제로 그려 눈으로 확인.
- 확인함(하단 메뉴·하트 백업, 가짜 Supabase 서버로 실제 앱 실행): 5칸 순서·현재 칸 표시, `/my?tab=` 이동과 탭을 눌렀을 때 새로고침 없이 하단 메뉴가 따라가는 것, 내용이 메뉴에 가려지지 않는 것(360px), `/admin` 화면에서는 메뉴가 숨겨지는 것, 하트 내려받기·합치기·바꾸기·없는 공연 건너뛰기·잘못된 파일 거부, 방문자에게 관리자 칸이 안 보이는 것 (27개, 실제 Chromium). 한글 파일명으로 저장되는지는 실제 브라우저에서 확인하지 못했어요(테스트 브라우저의 한계).
- 확인함(이벤트·팝업 광고, 가짜 Supabase 서버로 실제 앱 실행 + 실제 PostgreSQL 16): `0004` 권한·제약 36개 항목과 점검 스크립트(`rls_check.sql`)가 통과하고, 마이그레이션을 두 번 실행해도 오류가 없어요. 관리자 화면에서 이벤트·팝업 등록/수정/삭제/끄기와 잘못된 링크·날짜 차단 20개, 홈에서 기간 밖 이벤트·팝업 숨김, 끝나는 날 정렬, 팝업 여러 개 넘겨 보기, 팝업별 24시간 숨김 25개를 실제 Chromium으로 확인했어요. 이벤트·팝업이 하나도 없어도 홈은 정상이에요.
- 확인 못 함: 진짜 Supabase 프로젝트와의 연결, 실제 Supabase 로그인, 포스터 업로드, Vercel 배포. 배포 후 `DEPLOY.md`의 확인 순서대로 한 번씩 봐 주세요.
- 버전: Next.js 15, React 19, Tailwind CSS 3, TypeScript 5. (TypeScript 7은 Next.js 15에서 설정 파일을 읽지 못해 쓰지 않았어요)

## 광고 영역 (2종)

| 종류 | 위치 | 설정 |
| --- | --- | --- |
| 구글 애드센스 반응형 배너 | 메인 목록 카드 6개 뒤(6개 이하면 목록 맨 아래), 공연 상세 맨 아래 | `.env.local`의 `NEXT_PUBLIC_ADSENSE_CLIENT`, `..._SLOT_LIST`, `..._SLOT_DETAIL` |
| 팝업 광고 | 메인(`/`) 첫 진입 때만 | 관리자 화면 > 팝업 광고 탭 (여러 개, 기간 지정) |

**애드센스**
- 승인받은 뒤 발급된 `ca-pub-숫자`와 광고 단위(슬롯) ID를 환경변수에 넣고 다시 배포하면 `<ins class="adsbygoogle">`가 실제 광고로 채워져요. (`NEXT_PUBLIC_*` 값은 빌드 때 들어가므로 바꾸면 재배포가 필요해요.)
- ID를 비워 두거나 `ca-pub-XXXX…` 같은 자리표시자 그대로면: 개발 중(`npm run dev`)에는 점선 자리표시자가, 운영(`npm run build` 후)에는 아무것도 보이지 않아요.
- 스크립트는 `/admin` 아래에서는 불러오지 않아요. 광고 위에는 "광고" 표시가 붙어요.
- 광고 높이를 미리 잡아 두어 늦게 떠도 화면이 밀리지 않아요. 한 번만 `push({})` 하도록 막아 두었어요.

**팝업 광고 (관리자 화면에서 바꿔요)**
- 관리자 화면 > **팝업 광고** 탭에서 제목, 문구, 버튼 글자, 이동 링크, 이미지 주소, 배경색, 보이는 기간(시작·끝 날짜), 순서를 정해 여러 개 올려요. 지우지 않고 **끄기**만 할 수도 있어요. 코드를 고치거나 다시 배포할 필요가 없어요.
- 홈에 처음 들어올 때 '켜 둠 + 오늘이 기간 안'인 팝업만 떠요. 여러 개면 ◀ ▶로 한 장씩 넘겨 봐요. 순서 번호가 작은 것부터예요. **올린 팝업이 없으면 팝업은 안 떠요.**
- 오른쪽 위 **X**와 **닫기** 버튼, Esc, 바깥 클릭은 "이번만 닫기"예요. **오늘 하루 동안 보지 않기**를 누르면 지금 떠 있던 팝업들이 24시간 동안(팝업마다 LocalStorage 키 `jjabkit-popup-hide-v1`에 저장) 다시 안 떠요. 새로 올린 팝업은 다시 떠요.
- 이미지는 파일 업로드가 아니라 인터넷 주소(https://…)를 붙여 넣어요. 비우면 색 배경이에요. 링크에는 `rel="sponsored"`가 붙고, 링크·이미지 주소는 http(s)만 받아요.
- 예시 팝업 2개가 필요하면 `supabase/seed_popups.sql`을 한 번만 실행해요.

**운영 전에 꼭 확인하세요 (코드로 해결되지 않는 부분)**
- 애드센스는 사이트 심사 후 승인돼야 광고가 나와요. 승인 전에는 비어 있을 수 있어요.
- 개인정보처리방침 페이지와, 방문자에게 쿠키·맞춤 광고 동의를 받는 안내(동의 관리)가 필요해요. 특히 EEA·영국·스위스 방문자에게는 구글 인증 동의 관리 플랫폼 사용이 요구돼요. 이 프로젝트에는 아직 들어 있지 않아요.
- 내 광고를 내가 클릭하거나 클릭을 유도하는 것은 정책 위반이에요.

## 업데이트·소식, 이미지 저장·공유, 백업·복구

**소식 (What's New)**
- 상단 막대의 종 아이콘을 누르면 소식 모달이 열려요. 마지막으로 열어 본 뒤에 올라온 소식이 있으면 아이콘에 **N** 배지가 떠요. (열어 본 시각은 이 브라우저의 localStorage `jjabkit-notice-seen`에 저장돼요. 처음 방문하면 올라와 있는 소식이 모두 새 소식이에요.)
- 관리자 화면 > **소식·공지** 탭에서 등록·수정·삭제해요. 종류(신규 공연, 스케줄 변경, 업데이트, 공지), 연결할 공연(선택), 맨 위 고정을 고를 수 있어요. 공연 관리 탭의 **이 공연 소식 쓰기** 버튼을 누르면 그 공연이 연결된 초안이 채워져요. 자동으로 올라가지는 않아요. 직접 써서 올려요.
- 본문은 글자 그대로 보여줘요(HTML을 해석하지 않아서 스크립트가 들어가도 실행되지 않아요). 제목 100자, 본문 2000자까지.
- 저장: Supabase `notices` 표. 읽기는 누구나, 쓰기는 관리자만(RLS). 소식을 못 불러와도 다른 화면은 그대로 떠요.

**달력 이미지 저장·공유**
- 공연 상세의 캐스팅 달력 위, 마이페이지 > 관심 배우 일정 위에 **공유하기**와 **달력 이미지로 저장(PNG)** 버튼이 있어요. 지금 보고 있는 달을 그대로 그려요. 주간 보기에서도 그 주가 속한 달이 저장돼요.
- 캐스팅 달력 이미지에는 선택한 배우 필터가 반영돼요. 마이페이지 이미지는 체크가 켜진 관심 배우의 일정만 담겨요.
- 화면 테마(다크/라이트)와 상관없이 항상 밝은 배경으로 그려요. 이미지는 브라우저 안에서만 만들어지고 서버로 보내지 않아요.
- 공유하기: 파일 공유를 지원하는 브라우저(주로 휴대폰)에서는 PNG를 함께 공유해요. 지원하지 않으면 문구와 링크만 공유하고, 공유 기능이 아예 없으면 문구를 복사해요. 마이페이지는 내 브라우저에만 있는 내용이라 링크는 보내지 않아요.

**관리자 백업·복구 (JSON)**
- 관리자 화면 > **백업·복구** 탭. 내려받기는 공연 정보, 배역, 배우, 회차, 회차별 캐스팅을 파일 하나로 저장해요. 배역·배우를 이름으로 이어서 다른 DB로 옮겨도 복구돼요. 소식과 포스터 이미지 파일은 담기지 않아요(포스터는 주소만).
- 불러오기는 먼저 파일을 검사해요(5MB 이하, 형식·날짜·시간·중복 회차·없는 배역/배우, 포스터 주소는 http(s)만). 문제가 있으면 어디가 문제인지 보여주고 아무것도 바꾸지 않아요.
- 방식 3가지: 새 공연만 추가(제목이 같으면 건너뜀, 기본) / 모두 추가 / 전체 교체(지금 공연을 모두 지우고 파일로 바꿈, 확인 체크 필요). DB 함수 `import_shows()`가 한 번에 처리해서, 중간에 오류가 나면 전부 취소돼요. 전체 교체 전에는 꼭 먼저 내려받아 두세요.

## 하단 메뉴와 하트 백업

- 화면 아래에 항상 떠 있는 메뉴: **홈 / 관심공연 / 관심배우 / 내일정 / 데이터 백업**. 관리자 화면(`/admin`)에서는 숨겨요. 공연 상세는 홈으로 쳐요.
- 관심공연·관심배우·내일정은 마이페이지의 각 탭(`/my?tab=show`, `/my?tab=actor`, `/my?tab=sched`)으로 바로 가요. 관심 배우 일정은 메뉴 칸이 모자라 하단 메뉴에는 없고, 마이페이지 안의 탭(`/my?tab=fsched`)으로 가요. 마이페이지 안에서 탭을 눌러도 주소와 하단 메뉴가 같이 바뀌어요. (자세한 내용은 아래 '마이페이지 탭과 내 일정')
- **데이터 백업**(`/backup`)은 누구나 열 수 있어요. 하트(관심 공연·관심 배우)는 이 브라우저에만 저장되니, JSON 파일로 내려받아 두었다가 브라우저를 바꾸거나 사이트 데이터를 지운 뒤 불러올 수 있어요. 불러올 때 공연은 id가 달라졌어도 제목으로 찾아 맞추고, 지금 없는 공연은 건너뛰어요. 방식은 *합치기*(기본) / *파일 내용으로 바꾸기*예요.
- 관리자로 로그인한 경우에만 같은 화면에 **공연 데이터 백업·복구** 칸이 보이고, 누르면 `/admin?tab=backup`으로 가요. (보이는 것만 다르고, 실제 권한은 서버와 DB가 따로 지켜요.)

## 이벤트 (공연별)

- 이벤트는 **관리자 > 공연 관리**에서 공연을 고른 뒤 그 공연의 `이벤트` 영역에서만 만들어요. (예전의 별도 `이벤트` 탭은 없어졌어요.) 공연마다 따로 관리돼요.
- 영역 맨 위의 **`이 공연에 이벤트 있음`** 을 체크해야 입력 영역이 보여요. 체크를 끄면 입력 영역이 숨겨지고, 그 공연의 이벤트가 있으면 **모두 삭제**돼요(삭제 전에 확인을 물어봐요). 이벤트가 없는 공연은 체크가 꺼진 상태예요.
- 입력 항목은 **제목, 시작하는 날, 끝나는 날(비우면 하루만), 공지 링크(선택, http/https)** 이고, 달력 막대 색(선택)도 고를 수 있어요. 한 공연에 이벤트를 여러 개 올릴 수 있어요.
- 공연이 많아도 공연 선택 버튼에 `이벤트 N`이 붙어 어느 공연에 이벤트가 있는지 바로 보여요. 각 이벤트에는 진행 중/예정/종료와 기간이 표시돼요.
- 사용자 화면: 그 공연의 **캐스팅 달력**에 시작~끝나는 날만큼 이어진 막대로 보이고, 막대를 누르면 제목·기간·`공지 보기` 버튼이 열려요. '할인 & 이벤트' 탭 위에도 목록이 나와요. 홈 화면에는 나오지 않아요.
- 공연을 삭제하면 그 공연의 이벤트도 함께 삭제돼요. 이벤트는 공연 데이터 백업(JSON)에 포함되지 않아요.
- 예전에 올린 '장소'·'내용'은 더 쓰지 않아요(DB에는 남아 있지만 화면에 안 나와요). 공연에 연결하지 않고 올렸던 이벤트는 어디서도 보이지 않으니 필요하면 해당 공연에서 다시 등록해 주세요.
- 필요한 SQL: `supabase/migrations/0004_events_popups.sql` (0003 다음에 실행. 여러 번 실행해도 안전해요.)

## 안내 페이지 (소개 · 개인정보처리방침 · 문의)

- 화면 맨 아래(모든 화면 공통)에 `소개`, `개인정보처리방침`, `문의` 링크가 있고, 각각 `/about`, `/privacy`, `/contact` 로 열려요. 광고(애드센스) 심사에 필요한 페이지예요.
- 문구는 관리자 화면 > **안내 페이지** 탭에서 고쳐요. 저장하기 전에는 기본 문구가 보이고, `기본 문구로 되돌리기`로 언제든 되돌릴 수 있어요.
- 줄 앞 `## ` 은 소제목, `- ` 는 목록, 빈 줄은 문단 구분이에요. HTML은 해석하지 않고 글자 그대로 보여요.
- 기본 개인정보처리방침은 일반적인 예시예요(회원가입 없음, 하트는 기기에만 저장, 광고 쿠키 안내 등). 이메일 주소와 시행일은 직접 입력해야 하고, 실제 운영 상황에 맞는지 꼭 확인해 주세요. 법률 자문이 아니에요.
- 필요한 SQL: `supabase/migrations/0005_site_pages.sql` (없어도 기본 문구로 화면은 떠요). 안내 페이지 문구는 공연 데이터 백업(JSON)에 포함되지 않아요.

## 관리자 회차 달력 · 알림창 · 출연진 표시

- 관리자 > 공연 관리 > 캐스팅 스케줄의 **등록된 회차**는 기본이 **달력**이에요(`달력 | 목록` 전환 가능). 날짜를 누르면 그 날의 회차가 아래에 열려 고칠 수 있고, 위 `회차 추가`의 날짜도 그 날로 채워져요. 회차를 추가하면 그 달로 이동해요.
- 저장·추가·삭제가 되면 화면 아래에 **알림창**이 떠요(예: `회차가 추가되었습니다. (2026-12-12 14:00)`). 성공은 3.5초, 오류(권한 없음·같은 날짜·시간 중복 등)는 빨간색으로 7초 뒤에 사라지고 누르면 바로 닫혀요. 관리자 화면의 모든 탭에 같은 알림창이 적용돼요.
- 달력(사용자·관리자)의 회차 칸은 **앞 2명의 이름 뒤에 `…`** 를 붙여 더 많은 출연진이 있다는 걸 알려줘요. 칸을 누르면 전체 출연진이 열리고, 마우스를 올리면 전체 이름이 말풍선으로 보여요. 달력 이미지(PNG)에도 같은 `…`가 붙어요.

## 이벤트 막대 색

- 관리자 > 공연 관리 > 이벤트 영역에서 **달력 막대 색**을 고를 수 있어요: 기본색, 추천 8색, 또는 색 선택기로 직접. 아래 미리보기 막대로 바로 확인해요. `기본`을 고르면 원래 색(검정, 다크모드에서는 흰색)으로 돌아가요.
- 막대 글자색은 바탕색에 맞춰 흰색/검정이 자동으로 정해져요(노란색 같은 밝은 색에서도 읽혀요). 사용자 화면의 이벤트 목록 점, 이벤트 시트 위 띠에도 같은 색이 쓰여요.
- 필요한 SQL: `supabase/migrations/0006_event_color.sql`. 이걸 실행하기 전에도 이벤트는 그대로 보이고 색을 안 쓴 이벤트는 저장돼요. 색을 저장하려는데 아직 실행 전이면 안내 문구가 떠요.

## 반복 등록 · 링크 미리보기 · 오류 화면
- **회차 반복 등록**: 관리자 > 캐스팅 스케줄 > 회차 추가 > '반복 등록'. 시작일·종료일·요일·시간을 정하면 그 기간의 해당 요일마다 회차가 한 번에 만들어져요(캐스팅은 미정). 같은 날짜·시간이 이미 있으면 건너뛰고, 한 번에 최대 366일·200개예요. 날짜 계산은 `lib/repeatSessions.ts`예요. 새 SQL은 필요 없어요.
- **링크 미리보기**: 공연 상세 주소를 카톡·SNS에 붙이면 `공연이름 캐스팅 일정`과 기간·극장 설명, 포스터(http 주소일 때)가 보여요(`lib/shareMeta.ts`). 사이트 주소는 `NEXT_PUBLIC_SITE_URL`(없으면 Vercel 주소)을 써요.
- **오류·로딩·없는 페이지**: DB 연결이 안 될 때 `app/error.tsx`가 쉬운 문구와 다시 시도 버튼을 보여줘요(운영자용 안내에 오류 번호). 맨 바깥 오류는 `app/global-error.tsx`, 불러오는 중에는 `app/loading.tsx`, 없는 주소는 `app/not-found.tsx`예요.
- **조금 더 빠르게**: 첫 화면 공통 부분(로그인 확인·소식·팝업)을 순서대로 기다리지 않고 동시에 불러와요.
- 업로드 순서는 `docs/UPLOAD_CHECKLIST.md`를 따라 하세요.

## 공연 관리: 목록 · 검색 · 이벤트 유무 필터
- 관리자 > 공연 관리를 열면 공연이 한 줄에 하나씩 세로 목록으로 나와요(공연명만 표시, 이벤트 관련 표시는 붙이지 않아요).
- 맨 위에 **새 공연** 버튼, 그 아래에 공연명 **검색창**(입력하는 대로 걸러져요), **전체 / 이벤트 있음 / 이벤트 없음** 필터가 있어요. 검색과 필터는 함께 적용되고, 결과가 없으면 "검색 결과가 없습니다."가 나와요.
- 이벤트 유무는 필터로만 써요. 그 공연에 연결된 이벤트가 1개 이상이면 '이벤트 있음'이에요.
- 공연을 누르면 상세 관리 화면(기본 정보, 이벤트, 배역·배우, 캐스팅 스케줄, 수정·삭제, 소식 쓰기)이 열리고, '공연 목록' 버튼으로 돌아오면 검색어와 필터가 그대로 남아 있어요.

## 마이페이지 탭과 내 일정
- 마이페이지는 4개 탭이에요: **관심 공연 / 관심 배우 / 관심 배우 일정 / 내 일정**. 서로 다른 데이터를 보여줘요.
  - 관심 배우 일정(`?tab=fsched`): 예전 '내 일정'과 같아요. 하트로 등록한 관심 배우가 출연하는 모든 회차를 달력·목록으로 모아 보여줘요.
  - 내 일정(`?tab=sched`): 사용자가 **직접 '내 일정 추가'를 누른 회차만** 보여줘요. 관심 배우를 등록해도 자동으로 들어가지 않아요.
- 회차 정보 시트(공연 상세에서 날짜·회차를 누르면 나오는 화면)에 **내 일정 추가** 버튼이 있어요. 추가하면 버튼이 '일정 추가됨 · 내 일정 삭제'로 바뀌고, 다시 누르면 삭제돼요. 같은 회차는 한 번만 저장돼요(회차 고유 id 기준). 마이페이지 내 일정에서도 삭제 버튼과 회차 상세 보기가 있어요.
- 내 일정은 다가오는 일정이 날짜·시간순으로 먼저, 지난 일정은 아래에 따로 나와요. 비어 있으면 "아직 추가한 일정이 없습니다."와 추가 방법 안내가 나와요.
- 저장 위치: 이 브라우저의 `localStorage`(`jjabkit-mysched-v1`, 하트 `jjabkit-fav-v1`과 별개). 새로고침해도 남고, 공연에서 지워진 회차는 자동으로 정리돼요. 서버(Supabase)에는 저장하지 않아서 새 SQL은 필요 없어요. 하트 백업 파일에는 아직 포함되지 않아요.
- 회차 시트의 '예매처 바로가기'(인터파크·YES24·멜론티켓)는 제거했어요.

## 이용 안내 페이지 (관리자 등록 → 사용자 조회)
- 관리자 화면 `안내 페이지` 탭에서 안내 페이지를 **만들고, 고치고, 삭제**해요. 소개·개인정보처리방침·문의는 기본 페이지라 삭제는 안 되고 '기본 문구로 되돌리기'만 돼요.
- 사용자 화면에서는 **위쪽 책 아이콘(이용 안내)**, **화면 맨 아래 '이용 안내' 링크**, 또는 `/guide` 주소로 목록을 보고, 각 페이지(`/guide/주소`)를 읽기만 할 수 있어요. 수정·삭제 버튼은 사용자에게 보이지 않고, DB 보안 규칙(RLS)도 관리자만 쓰게 막아 둬요.
- 같은 표(`site_pages`)를 관리자와 사용자가 함께 써요. 데이터를 따로 복사하지 않아서 관리자가 고치면 바로 반영되고, 삭제하면 사용자 목록에서도 사라져요.
- 새 페이지의 주소(slug)는 영문 소문자·숫자·하이픈(-), 40자까지예요. `about`, `privacy`, `contact`, `new`는 쓸 수 없어요.
- 필요한 SQL: `supabase/migrations/0007_site_pages_custom.sql`. 실행 전에도 기본 3개 페이지와 이용 안내 목록은 그대로 보이고, 새 페이지를 만들려고 하면 안내 문구가 떠요.

## 사용자 편의 기능 (홈 빠른 보기 · 배우 출연 회차 · 내 일정 백업/캘린더)
- **홈 빠른 보기(오늘/이번 주말)는 없앴어요**. 날짜별 공연은 아래 '메인 · 오늘 탭'의 오늘 탭에서 봐요.
- **내 다음 일정 한 줄**: 이제 '오늘' 탭 맨 위에 보여요(D-3 공연명 · 19:30, 누르면 그 회차 상세).
- **배우 검색**: 메인 검색창에 배우 이름을 넣으면 그 배우가 나오는 공연의 제목만 남아요(출연 회차 숫자는 이제 표시하지 않아요).
- **내 일정 백업**: 데이터 백업 파일(JSON)에 내 일정이 함께 들어가요(`mySessions`: id·공연명·날짜·시간). 공연 데이터를 다시 만들어 id가 바뀌었어도 공연명+날짜+시간으로 찾아 맞춰요. 내 일정이 없는 예전 백업 파일은 그대로 불러와지고, 이때 지금 내 일정은 건드리지 않아요.
- **캘린더에 저장(.ics)**: 마이페이지 `내 일정` 탭의 버튼. 다가오는 일정을 .ics 파일로 내려받아 열면 폰·구글·네이버 캘린더에 들어가요(공연장, 출연진, 하루 전·2시간 전 알림 포함, 상영 시간은 공연 정보의 '러닝타임' 글자에서 읽고 못 읽으면 150분). 한국 시간(Asia/Seoul) 기준이에요.
- 새 SQL은 없어요(DB 변경 없음).

## 관리자 편의 기능 (회차 일괄 작업 · 실행 취소 · 저장 안 됨 경고)
- **회차 목록**: 한 줄에 날짜·시간·배역별 배우 선택이 있어서 바로 고칠 수 있어요.
- **일괄 작업**: 회차 앞 체크박스(또는 "보이는 회차 모두 선택")로 고르면 위에 작업 줄이 떠요. 배역 하나의 배우를 한꺼번에 배정 / 다른 회차의 캐스팅 복사 / 시간 변경(같은 날 같은 시간 회차가 있으면 건너뜀) / 선택 삭제(확인 후).
- **실행 취소**: 회차·공연 삭제와 일괄 수정 뒤 알림에 `실행 취소`가 떠요(10초). 삭제한 행을 원래 id로 되살려서 사용자의 내 일정·하트도 유지돼요. 배역/배우 삭제는 아직 대상이 아니에요.
- **저장 안 됨 경고**: 입력만 하고 등록하지 않은 폼이 있으면 위에 알림 띠가 뜨고, 탭·목록 이동·로그아웃·새로고침 때 확인해요.
- **커튼콜/타임세일**: 관리자 회차 화면의 체크박스·아이콘은 없앴어요. 타임세일은 이후 공연 상세(달력·회차 시트·할인&이벤트 카드)·내 일정·캘린더 이미지·.ics에서도 표시와 코드를 모두 제거했어요. DB의 `is_time_sale` 열과 백업 JSON의 `timesale` 값은 기존 데이터·백업 호환을 위해 그대로 두고 저장 시 값만 전달해요(화면에는 쓰지 않아요).
- 새 SQL은 없어요.

## 메인 · 오늘 탭
- **메인(/)**: 포스터·카드 없이 **공연명만** 세로 리스트로 보여 줘요. `전체/뮤지컬/연극`, `전체/공연 중/개막 예정` 필터와 검색은 그대로예요. 줄 오른쪽 하트로 관심 공연 등록, 줄을 누르면 공연 상세로 가요. 공연이 늘면 리스트가 그만큼 길어져요.
- **오늘 탭(/today)**: 아래 메뉴의 `오늘`. 고른 날짜(기본은 오늘, 한국 시간)에 열리는 공연을 공연별 → 회차 시간순으로 보여 주고, 각 회차에 **그 회차에 실제 연결된 배우**를 배역 순서대로 `A · B · C`로 보여 줘요. 배우가 하나도 없는 회차는 `캐스트 정보 없음`이에요.
- **날짜 선택**: 오늘 탭 안의 ◀ / 날짜 입력 / ▶ 와 `오늘로` 버튼. 날짜는 주소(`/today?d=2026-11-15`)에도 들어가서 뒤로 가기·공유해도 같은 날이 보여요. 잘못된 날짜는 오늘로 처리해요.
- **회차 상세**: 오늘 탭의 회차를 누르면 `/shows/공연id?d=날짜&s=회차id`로 가서 그 회차의 캐스트와 `내 일정 추가`가 바로 열려요. 없는 회차 주소면 시트 없이 공연 상세만 보여요.
- DB 변경·새 SQL은 없어요. 하드코딩된 공연·배우 없이 `fetchShows` 데이터를 그대로 써요.

## 안정성 개선 (0008)
- **한 번에 처리(원자성)**: 회차 일괄 수정·삭제, 공연 삭제·되돌리기는 DB 함수(`delete_sessions`, `bulk_update_sessions`, `restore_sessions`, `delete_show_bundle`, `restore_show_bundle`) 한 번으로 실행돼요. 중간에 실패하면 전부 취소돼서 반쪽 데이터가 남지 않아요. 필요한 SQL: `supabase/migrations/0008_atomic_admin_ops.sql` (여러 번 실행해도 안전, 기존 마이그레이션은 수정하지 않았어요).
- **되돌리기**: 원래 ID로 복원하므로 사용자의 하트·내 일정이 유지돼요. 복원 시 사라진 배우가 있으면 해당 배역만 '미정'이 되고 안내 문구에 개수가 표시돼요.
- **다른 공연 배우 섞임 방지**: 회차와 배역이 서로 다른 공연이면 DB가 막아요(트리거). 실행 시 기존에 섞인 행이 있으면 개수를 알려줘요(정상이면 0).
- **한국 시간(KST)**: 오늘 기준은 항상 KST이고 자정이 지나면 자동 갱신돼요. 오늘 탭 날짜는 주소(`?d=`)가 기준이라 뒤로가기가 정확해요.
- **캘린더(.ics)**: RFC 5545 규칙(특수문자 이스케이프, 75바이트 줄 접기, Asia/Seoul 시간대)을 따라요.
- **접근성**: 회차 시트는 포커스가 안에 머물고 Esc로 닫혀요. 모바일 버튼·체크박스는 44px 이상이에요.
- **오류 처리**: 표가 아직 없을 때(SQL 미실행)만 빈 화면/기본값, 그 외 DB 오류는 오류 화면(다시 시도)으로 보여요. 소식·팝업은 실패해도 본문은 뜨고 로그만 남겨요.
- **DB 검증 스크립트**: `supabase/tests/atomic_ops_check.sh` (+`stubs.sql`). 로컬 PostgreSQL 16을 직접 띄워 실행하는 용도예요(스크립트 상단의 접속값 참고).

## 캐스팅 확인·관심 배우 편의 개선
DB 변경(마이그레이션)과 새 패키지는 없어요. 저장 키·백업 JSON v1·공연/배우/배역/회차 ID는 그대로예요.
- **검색(홈)**: 공연명·장르·배우 이름으로 찾아요(공연장은 검색 대상이 아니에요). 이름 일부·띄어쓰기 차이도 찾고, 배우가 일치하면 목록에서 `배우(배역)`을 강조해 보여줘요(최대 3명 + 외 N명). × 버튼과 '검색 조건 초기화'가 있어요. 공연 목록은 요청하신 대로 제목만 있는 리스트를 유지해요.
- **정렬**: 기본순 / 공연명순 / 개막일순 / 종료일순. 날짜가 없는 공연은 맨 뒤예요. '최근 등록순'은 등록일 데이터가 없어 넣지 않았어요.
- **최근 본 공연**: 공연 상세를 열면 이 브라우저(`jjabkit-recent-v1`)에만 최대 8개 저장하고, 홈 상단에 보여줘요(검색 중엔 숨김, '기록 지우기'). 서버로 보내지 않고 백업 파일에는 포함되지 않아요.
- **캐스팅 달력 빠른 이동**: 오늘 / 다음 회차(해당 회차 시트 바로 열림) / 첫 회차 / 마지막 회차. 배우를 골라 둔 상태에서는 '다음 출연 회차'가 되어 그 배우가 나오는 회차만 대상으로 해요. 월간·주간 모두 동작하고, 없을 때는 안내 문구가 떠요. 기준은 한국 시간이에요.
- **배우 필터**: 배우가 8명을 넘으면 처음엔 접혀 있고 선택한 배우는 요약 칩으로 보여요(칩을 누르면 해제). 배역별 접기/펼치기, 배우 이름 검색, 선택한 배우만 보기, 초기화, 조건에 맞는 회차가 없을 때 안내가 있어요. 기존 하트·'관심 배우만'·'해당 회차만'은 그대로예요.
- **관심 배우 일정(마이페이지)**: 전체 선택/해제, 선택 수, 이름 검색(7명부터), 선택한 배우만 보기, '함께 출연하는 회차만'(2명 이상 선택 시, 여러 배우를 비교해 같이 나오는 회차 찾기), 가장 가까운 출연 카드, 선택한 배우의 앞으로 일정 `.ics` 저장(파일명 `jjabkit-배우_외N명-날짜.ics`, 같은 회차는 한 번만, 제목에 배우 이름 표시). 기존 '내 일정' `.ics`는 그대로예요.
- **내 일정**: 맨 위에 가장 가까운 관람(D-day·날짜·공연장·캐스팅) 카드. 일정이 없으면 오늘 공연/공연 목록으로 가는 버튼을 보여줘요.
- **하단 메뉴**: 홈/오늘공연/마이페이지/데이터 백업 구성을 유지했어요(마이페이지 안에 관심 공연·관심 배우·관심 배우 일정·내 일정 탭이 이미 있어요).
- 제외한 항목: 공연장 검색(요청에 따라 구현하지 않음), 공연별 메모(우선순위 낮음·데이터 관리 부담 → 제안만).

## 공연 상태 자동 판정
- 공연 상태(개막 예정 / 공연 중 / 공연 종료)는 **저장하지 않고** 개막일·종료일과 오늘(한국 시간, KST)로 계산해요(`lib/status.ts`). 개막일 전 = 개막 예정, 개막일~종료일(양 끝 당일 포함) = 공연 중, 종료일 다음 날부터 = 공연 종료.
- 날짜만 바뀌면 되므로 Cron·스케줄러·DB 변경이 필요 없어요. 기존 공연 전부에 바로 적용돼요. 화면을 열어 둔 채 KST 자정이 지나도 목록 탭·상세 태그가 저절로 바뀌어요. 기기 시간대는 영향을 주지 않아요.
- 사용자 화면: 목록 상태 탭(전체 / 공연 중 / 개막 예정 / 종료), 공연 카드·상세 태그, 링크 미리보기 문구가 같은 계산을 써요.
- 관리자: 상태 선택칸을 없애고 개막일·종료일만 입력해요. 날짜를 바꾸면 상태가 바로 다시 계산돼서 보이고, 공연 목록에도 상태가 표시돼요. 종료일이 개막일보다 빠른 입력은 저장하지 않고 안내해요(일정을 뒤로 옮길 때는 종료일 먼저, 앞으로 옮길 때는 개막일 먼저).
- 날짜가 비었거나 한쪽만 있거나 순서가 어긋난 공연은 상태를 짐작하지 않고 '일정 미정'으로 보여요(전체 탭에만 나와요).
- DB의 `shows.status` 열은 더 이상 읽지 않아요(지우지 않아 기존 데이터·백업과 호환). 백업 JSON v1의 `status`는 참고용 값(running/upcoming)으로 계속 내보내고, 예전 백업도 그대로 불러와요.

## 내 일정 월간 달력
- 마이페이지 '내 일정' 탭의 카드 목록을 월간 달력(`components/my/MySchedCalendar.tsx`)으로 바꿨어요. 저장 방식(`jjabkit-mysched-v1`)·구조·추가/삭제·ICS(`buildIcs(upcoming)`, 시작 시각 KST 기준 앞으로 일정만)는 그대로예요.
- 달: 이전/다음 달, '오늘'. 오늘 강조, 지난 회차는 흐리게, 일정 있는 날은 점 표시. 한 칸에 모바일 2개·데스크톱 3개까지 보이고 나머지는 '+N개' → 날짜를 선택하면 아래에 전부 나와요.
- 일정을 누르면 상세(공연명·날짜·시간·장소·캐스트). 삭제는 확인 단계를 거치고 달력에 즉시 반영돼요. '회차 전체 보기'로 기존 회차 시트도 열려요.
- DB·마이그레이션 변경 없음.

## 오늘 공연 - 이벤트 배지
- 이벤트는 회차가 아니라 **공연 + 기간(시작일~종료일, 종료일이 없으면 하루)** 에 연결돼 있어요(`events` 표, 관리자가 공연 관리에서 등록). 그래서 오늘 탭은 선택한 날짜가 기간에 들어가는 그 공연의 이벤트를, 그 날 그 공연의 모든 회차에 보여요. (`lib/today.ts`의 `eventsOnDate`)
- 화면은 시간대별 표예요: 시작 시간 제목 아래에 줄마다 [공연 색 칸 | 이벤트 배지 + 캐스트]. 극이 많아도 같은 시간대끼리 묶여 한눈에 보여요.
- 시작일이 없는 이벤트는 적용 범위를 알 수 없어 표시하지 않아요. 공지 링크(http/https)가 있으면 배지가 새 탭 링크, 없으면 눌리지 않는 배지예요.
- 이벤트를 불러오지 못해도 공연·캐스트 화면은 그대로 떠요. DB 변경 없음.

## 공연별 스케줄 색 (0009)
- 관리자 > 공연 관리 > 공연 기본 정보의 '스케줄 색상'에서 팔레트 9색·색상 선택기·HEX 코드 중 편한 방법으로 고르면 바로 저장돼요. 색은 공연(`shows.schedule_color`)에 한 번만 저장하고 회차마다 따로 저장하지 않아요.
- 이 색은 그 공연의 모든 회차 카드(사용자 캐스팅 달력, 관리자 캐스팅 스케줄 달력, 내 일정·관심 배우 달력, 오늘 공연, 달력 PNG)에 같은 색으로 쓰여요. 고르지 않은 공연은 포스터 색을 대신 써요.
- 글자색은 배경색에 맞춰 흰색/검정 중 대비가 큰 쪽으로 자동으로 정해져요(어떤 색에서도 대비 4.5:1 이상).
- `0009_show_color.sql`을 아직 안 돌린 DB에서도 기존 기능은 그대로 되고, 색을 저장할 때만 안내가 떠요. 백업 JSON에도 색(`color`)이 들어가요.
