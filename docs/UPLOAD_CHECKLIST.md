# 업로드 점검표 (집에서 한 번에)

위에서부터 순서대로 하면 돼요. 각 단계 끝의 "확인"이 맞으면 다음으로 넘어가세요.

## 1. Supabase — SQL 실행 (이미 한 것은 건너뛰어도 돼요)
Supabase 대시보드 > SQL Editor에서 아래 파일 내용을 하나씩 붙여넣고 Run 해요. 전부 여러 번 실행해도 안전해요.

- [ ] `supabase/migrations/0004_events_popups.sql`
- [ ] `supabase/migrations/0005_site_pages.sql`
- [ ] `supabase/migrations/0006_event_color.sql`
- [ ] `supabase/migrations/0007_site_pages_custom.sql` (관리자가 안내 페이지를 새로 만들 때 필요)

확인: 실행 후 "Success"가 나오고 빨간 오류가 없어요.
(0001, 0003은 처음 만들 때 실행했다면 다시 안 해도 돼요.)

## 2. GitHub — 소스 올리기
- [ ] 이 ZIP의 압축을 풀어요.
- [ ] 저장소의 기존 파일 위에 덮어쓰기로 올려요. (`.env.local`은 올리지 않아요)
- [ ] 지워진 파일이 있어요: `components/admin/EventsAdmin.tsx`. 저장소에서도 삭제해 주세요. (남아 있으면 빌드가 실패할 수 있어요)

확인: GitHub 저장소에 `components/admin/ShowEventsEditor.tsx`, `lib/repeatSessions.ts`, `app/global-error.tsx`가 보여요.

## 3. Vercel — 배포 확인
- [ ] 올리면 자동으로 배포가 시작돼요. Deployments에서 상태가 **Ready**가 될 때까지 기다려요.
- [ ] **Error**면 로그의 빨간 줄을 캡처해서 알려주세요.
- [ ] (선택) Environment Variables에 `NEXT_PUBLIC_SITE_URL`을 추가해요. 값은 사이트 주소(예: `https://내주소.vercel.app`). 나중에 도메인을 사면 새 주소로 바꾸고 다시 배포해요. 없어도 동작은 해요.

## 4. 동작 확인 (사용자 화면)
- [ ] 첫 화면에 공연 목록이 나와요.
- [ ] 공연을 열면 캐스팅 달력이 나와요.
- [ ] 하단 메뉴 > 소개 / 개인정보처리방침 / 문의 페이지가 열려요.

- [ ] 공연 > 날짜의 회차를 눌러 **내 일정 추가**를 눌러요. 버튼이 '일정 추가됨 · 내 일정 삭제'로 바뀌어요.
- [ ] 마이페이지 > **내 일정**에 방금 추가한 회차가 보이고, 새로고침해도 남아 있어요.
- [ ] 마이페이지 탭이 4개예요: 관심 공연 / 관심 배우 / 관심 배우 일정 / 내 일정.
- [ ] 회차 시트에 예매처(인터파크 등) 버튼이 더 이상 없어요.

## 5. 동작 확인 (관리자)
- [ ] 관리자 로그인이 돼요.
- [ ] 탭이 5개예요: 공연 관리 / 팝업 광고 / 소식·공지 / 안내 페이지 / 백업·복구.
- [ ] 공연 관리 > 공연 선택 > **이벤트** 구역에서 체크 → 이벤트 추가 → "이벤트가 추가되었습니다." 알림이 떠요.
- [ ] 같은 공연의 캐스팅 스케줄 > 회차 추가 > **반복 등록**으로 기간·요일·시간을 정하고 만들어 봐요. (테스트 공연으로 해보고 지워도 돼요)
- [ ] 등록된 회차 달력에 이벤트 막대가 같이 보여요.
- [ ] 사용자 화면의 같은 공연에도 막대가 보이고, 누르면 '공지 보기'가 열려요.

## 6. 안내 페이지 문구
- [ ] 관리자 > 안내 페이지에서 개인정보처리방침의 **이메일**과 **시행일**을 실제 값으로 바꿔요. (광고 신청 전에 꼭 필요해요)

## 7. 링크 미리보기 확인 (선택)
- [ ] 공연 상세 링크를 카카오톡 "나에게 보내기"에 붙여넣어 제목이 `공연이름 캐스팅 일정`으로 보이는지 확인해요.
- 포스터 이미지가 있는 공연은 포스터가 같이 보여요. 카톡은 미리보기를 잠시 기억(캐시)해서, 고친 뒤에도 옛 모습이 보일 수 있어요.

## 문제가 생기면
- "잠시 문제가 생겼어요" 화면 → 아래 '운영자용 안내'를 펼쳐 오류 번호를 확인하고, Vercel > Logs에서 같은 번호를 찾아요.
- 이벤트 저장 시 "DB에 …sql 이 아직 적용되지 않았어요" → 1단계의 해당 SQL을 실행해요.
- 자세한 내용은 `DEPLOY.md`를 봐요.
