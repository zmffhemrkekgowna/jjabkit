## 이번에 고친 것
1. **저장 데이터 보호** — `MyPage.tsx`, `ShowList.tsx`: 서버가 공연 목록을 빈 배열로 돌려주면(DB 점검·복구 중 등) 관심 공연·내 일정이 "없는 ID"로 보고 자동 정리돼 사라질 수 있었어요. 공연이 0개일 땐 정리를 건너뛰어요. (빈 DB 시나리오 브라우저 테스트로 확인)
2. **내 일정 상세창 접근성** — `MySchedCalendar.tsx`: 포커스 가두기·Esc·배경 스크롤 잠금·닫은 뒤 포커스 복귀가 없어 다른 모달(`useDialogFocus`)과 달랐어요. 같은 훅으로 맞췄어요.
3. **개인정보처리방침 기본 문구** — `lib/pageDefaults.ts`: localStorage에 저장되는 항목에 내 일정·최근 본 공연·팝업/공지 숨김 설정이 빠져 있었어요. 실제 저장 방식에 맞춰 보완했어요. (관리자가 DB에서 이미 수정한 문구는 그대로 두며 자동으로 바뀌지 않아요 → 관리자 화면 '안내 페이지'에서 확인)
4. 오류 화면의 운영자 안내 문구 `SQL(0001~0006)` → `0001~0008`.

## 확인했지만 고치지 않은 것 (사유)
- **복구(교체) 시 공연 ID가 새로 만들어져요.** 백업 JSON은 설계상 ID 없이 이름으로 연결(이식성). 그래서 관리자가 '복구-교체'를 하면 이용자 브라우저의 관심 공연·내 일정 ID는 더 이상 맞지 않아요. 이용자 쪽 '하트·내 일정 백업'은 제목/날짜/시간으로 다시 맞추므로, 복구 후 이용자는 그 백업으로 되살릴 수 있어요. 백업 형식 변경은 사전 승인이 필요한 항목이라 바꾸지 않았어요.
- 광고 동의(CMP) 배너는 없어요. AdSense 키를 설정해 광고를 켜기 전에 동의 관리 도구를 붙여야 해요(방침 문구는 쿠키·광고 설정 안내만 있어요).
- `npm audit`: Next.js 내부 postcss 취약점 2건(빌드 시 CSS 처리 경로). 해결에 Next 메이저 업그레이드가 필요해 보류.
- 320px 폭에서 일부 화면 가로 스크롤(기존 테스트 `pwbars`, 점검 전 빌드에서도 동일). 기준 해상도(360px 이상)에서는 없어요.
